# Ethical GitHub growth plan

## Before launch

Validate setup, publish a real example and document limitations. Adopt contribution/security/conduct files, configure accurate topics and create a readable social preview. Do not display CI badges until the workflows run in the public repository.

## Weeks 1–4

Publish a concrete demo of partial-success reporting and heuristic limitations. Invite feedback from developers who prefer explicit task state. Create bounded issues from observed friction, respond to reproducible reports and record corrections. Share relevant technical explanations in communities where project posts are welcome; avoid unsolicited mass messaging.

## Months 2–3

Publish a real-edit fixture and evidence export when they exist. Write tutorials on approval binding, interruption recovery and evaluation coverage. Include competitor comparisons only with compatible protocols and evidence. Invite independent reproduction rather than asserting superiority.

## Measures

Track first-run completion, evidence-backed task success, contributor retention and unresolved reproducible bugs. Stars are secondary. No star buying, engagement exchange, fabricated benchmarks, mass issue spam or ranking guarantee.

Proposed repository description: User-first coding-agent harness for clear task state, evidence-aware responses and reproducible evaluations. Preview available; scoped execution under development.

Suggested topics, where accurate: coding-agent, agent-harness, developer-tools, accessibility, local-first, evaluation, typescript, python.
